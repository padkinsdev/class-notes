# CSRF and XSS

### Content Security Policy (CSP)
- Defined by a web server to be enforced by a browser
- Instructs the browser to only use resources loaded from specific sources
- Disallows inline scripts and/or allows scripts only from certain domains
- Also works with iframes, images, etc.
- Server specifies policy with `Content-Security-Policy` http header

### Tricking users into making http requests
- General theme: Trick the user into making a malicious action while thinking they're doing something benign
- **Clickjacking**: Trick the victim into clicking something from the attacker
- **Phishing**: Trick the victim into divulging sensitive information

#### Clickjacking
- **Invisible iframes**: Superimpose invisible malicious content over enticing content such that the user's click triggers the malicious content. Alternatively, superimpose small elements over a larger piece of content to alter the content
- **Temporal attack**: Using JavaScript to detect the cursor position and change website content right before the user clicks
- **Cursorjacking**: Creating a fake cursor with CSS/HTML/JS that is constantly a fixed distance from the real cursor

##### Defenses
- Delay the click by forcing a user to hover over the desired content for some amount of time before they can click
- Create clear visual cues for where the intended click location is
- Confirmation pop-ups to ensure that the user is intentionally performing an action
- **Frame-busting**: The legitimate website forbids other vebsites from embedding it in an iframe. This defeats invisible frame attacks and can be enforced by CSP or the `X-Frame-Options` HTTP header. A drawback is that this depends on the end-user's browser enforcing their own security

#### Phishing
- Relies on the user being unable to differentiate between a legitimate site or piece of content and a malicious one
- Mostly involves users voluntarily disclosing information to attackers via deceptive web forms, etc.
- **Homograph attack**: Creating malicious URLs that resemble real ones for impersonation purposes. Can be foiled by checking certificate issuance information/legitimacy/etc.
- **Browser in browser attack**: Using CSS/HTML/JS to create a fake browser window within a malicious webpage such that it appears to the user that they have two browser windows open

##### Defenses and Drawbacks
- **2FA/MFA**: Require additional information that the user knows (password, security question), has (phone, security key), or is (fingerprint, face ID). A common example is 2FA authentication codes, generated by a 2FA authentication app
    * Token and server share a common secret key `k`. WHen the user wants to log in, the token generates a code `HMAC(k, time)` which can only be used for a limited amount of time
    * **Man in the Middle attack/Relay attack**: Convincing the user to also disclose their 2FA auth code to the attacker, thus allowing the attacker to relay both the user credentials *and* 2FA auth code
    * **Brute force attacks**: Spamming guesses until the correct one is found
    * **Social Engineering**: When 2FA codes are sent via SMS, an attacker can get a phone provider to activate their SIM, thus intercepting texts. Additionally, customer support can be used to circumvent 2FA and/or disable 2FA entirely

### CAPTCHAs
- Completely Automated Public Turing Test to tell Computers and Humans Apart
- Also called a "reverse Turing test"
- Used to distinguish web requests from humans from those made by bots
- Modern CAPTCHAs have also been co-opted by companies to train AI models without paying humans. This also presents issues by training machines to bypass the CAPTCHAs that were initially meant to serve the opposite purpose
- There is ultimately a resulting arms race where CAPTCHAs must become more and more difficult as machines become better at solving them. As a result, CAPTCHAs can become too difficult or vague for even humans to solve them
- **Outsourcing attack**: Pay humans to solve CAPTCHAs for you, thus eliminating the barrier. This is generally exceedingly cheap (a few cents per CAPTCHA), making security a fundamentally economic issue. 
- ***If paying a small amount of money to bypass a security measure will yield a larger amount of money, the security measure is functionally nonexistent***

### What is security?
- Enforcing a desired property in the presence of an attacker
- Cryptography preserves three properties: confidentiality (content is only legible to the intended parties), integrity (content cannot be changed without alerting those involved), and authenticity (the source is verified)
