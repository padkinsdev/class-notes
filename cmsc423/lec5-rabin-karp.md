# Exact String Matching (Rabin-Karp)

## Introduction
- String fingerprints give O(n) expected-time exact matching
- Rabin-Karp is a probabilistic approach that compares short fingerprints from the source text with the fingerprint of the query string
    - Essentially, comparing hashes of the query string and sections of the source string
    - The fingerprint of the next window can be derived from the current one in O(1) time, so this is a rolling hash
    - Equal fingerprints don't prove string equivalence (due to hash collisions), so every candidate match is verified character by character
    - The expected time complexity of Rabin-Karp is O(n)

## Principle
- Idea: For each character in a string T[s...s+m-1], a numerical representation can be generated by multiplying each character by $d^{m-i}$ where d is the number of characters in the alphabet, and i is the position of a given character relative to the beginning.
- Evaluating the polynomial term by term costs O(m) multiplications and builds enormous intermediate values. Using Horner's rule we can instead do $`p = P[m-1] + 10*(P([m-2]) + 10*(P[m-3] + ... + 10*P[0]...))`$, that is, $`p \leftarrow (d*p+P[i])`$ repeated for i=0...m-1
    - One multiply and one add per character means O(m) time, and with a (mod q) on each step the running value never exceeds q
    - The same loop over $T[0...m-1]$ produces $t_0$
- To roll the hash over to the next position, subtract the leading character (scaled by $h = d_{m-1}$), shift everything left by multiplying by d, then add the incoming character. This leads to constant work per shift
